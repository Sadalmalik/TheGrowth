# TheGrowth — контекст проекта

Карточная игра с визуальными новеллами и ветвящимся сюжетом. Карты работают как фишки на поле.
Стилизация — карты Таро и гадальные карты. Product name в Unity — Thraumatrope. Делается автором
и друзьями вечерами, цель — релиз в Steam. Аудитория — девушки, далёкие от IT (моддинга нет).

Unity 6000.3 (C# 9). Платформы: PC (Steam), вероятно Android, iOS, Web (itch.io); macOS нет.
Плагины: DOTween, Odin Inspector (уходим), Naninovel (уходим — своя диалоговая система).
Планируются: UniTask, R3 + ObservableCollections, Spine.

Код прототипа: `Assets/_XandArt/TheGrowth/Code`. Контент: `Assets/_XandArt/TheGrowth`.

## Архитектура (кратко)

- **Жизненный цикл** — `GameFlow` единственный владелец переходов. Scopes Global → Session →
  Location. Новая игра и загрузка — один путь `CreateSession(SaveGame)`. Без статики.
  Сцена `Main` постоянная, остальные additive; сцена локации — `LocationRoot`. Сохранение —
  `SaveGameRequest`, ждёт точки сохранения. Play из любой сцены — пресет `StoryStep`.
- **Данные** — конфиги (SO, `int Id` на тип), runtime-состояние (C# классы в системах сессии),
  сейв (DTO с версией).
- **Карта** — `CardModel` → `CardInstance` → `CardSave`. Именованные переменные карты вместо `Charges`.
- **Переменные** — объявляются в конфигах; области: игра (слот), карта, профиль (вне слотов);
  типы `bool` / `int` / `string`; в скриптах `$имя` и `[карта].имя`.
- **Слоты** — слот — место, куда кладётся одна или несколько карт (колода, рука, клетка поля,
  слот крафта). Карта всегда ровно в одном слоте. Инвентарь — это колода, стаков нет.
- **Сохранения** — zip на слот, ручные без лимита + 3 автосейва по кругу. Посреди экспедиции —
  можно, в диалоге — когда он ждёт игрока; команда `autosave` в диалогах.
- **Логика** — команды асинхронные (UniTask), кондишены и эвалуаторы синхронны; реакции карт срабатывают сразу (вложенно). Каждый скрипт
  завершается; сохраняться можно только без активных скриптов (кроме диалога, ждущего игрока); игра строго пошаговая. Во время
  скриптов и анимаций карты недоступны, UI доступен. Цель — только перетаскиванием.
- **Скрипты** — только система команд (Lua не используем). Хранятся текстом на своём языке —
  тот же текст, что рисует инспектор (rich-текст, как триггеры Warcraft 3). Файл на карту, хуки
  секциями (`OnPlaced`), общеигровые хуки — отдельным файлом. `Parallel` / `Background`.
  Диалоги — отдельные файлы (граница диалога = файл), команды разрешены по контексту
  (везде / только в диалогах / только вне).
- **Отображение** — 3D (хаб 2.5D), одна вьюха карты, минимальный UI. UI — MVVM на R3.
  Текущее управление камерой сохранить.
- **Код** — слои сверху вниз: Game → Presentation/UI → Model → Core → Architecture; по сборке на слой
  (`Code/<Слой>/`), модули папками. Зависимости только вниз; наверх — через интерфейсы нижнего слоя и события
  `EventBus`. Model не зависит от сцены. Всё, что зависит от внешнего мира (платформы, аналитика,
  хранилища сохранений), — модули-интеграции (сборка на модуль), подключаются через DI в Game.
  Сквозные системы: ядро в Core (сохранения, локализация, аналитика, игровые сервисы, настройки). Приватные поля — `m_Field`; namespace только с телом.
- **Процедурные анимации** — `AnimationProfile` (Architecture); наборы
  анимаций карт и слотов — конфиги Presentation.

## Правила работы Claude

- Краткость. Обсуждать по частям, не проектировать наперёд то, что автор не обсуждал.
- Перед работой над системой — прочитать соответствующий `.claude/architecture-*.md`.
- Изменилось решение — обновить `.claude`, эту выжимку и страницу в `.docs`.
- Вопросы — только в `.docs/Вопросы.md`, не задачами.
- Схемы зависимостей: слои горизонтально сверху вниз, элементы слоя в строку; вниз — сплошные
  стрелки, вверх (интерфейсы, события) — пунктирные. Поток вызовов — отдельной схемой.
- Задачи — в `.docs/tasks/` по шаблону `.docs/_templates/Задача.md`; обновлять `status`.
- Код прототипа не расширять.
