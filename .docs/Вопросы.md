[[Главная]]

Открытые вопросы и принятые по ним решения. Вопросы не заводятся задачами — только здесь.

## Открытые

1. **Отмена карты и зум.** Как разделить отмену использования карты и зум (сейчас оба на ПКМ)?
   *Кто: RENEMARO.*
2. **`else if`.** Повторяющиеся секции в шаблоне не описываются. Предложение: пока вложенный `if`
   внутри `else`, позже инспектор показывает их одной строкой `else if`. *Кто: автор.*
3. **Скобки внутри вложенного узла.** Если брать в скобки каждый параметр, получится
   `[charge [>] [1]]`. Предложение: скобками выделяются вложенные узлы (эвалуаторы, условия) и
   литералы на уровне команды; литералы внутри вложенного узла — без скобок, редактируются в его
   панели: `[charge > 1]`. *Кто: автор.*

4. **Сохранение внутри диалога.** Сейчас запрещено, но у дизайнера — быстрое сохранение в окне
   диалога и автосейв из скрипта. Вариант Б: разрешить в точках ожидания игрока; сохраняется
   позиция исполнения + состояние сцены (фон, персонажи, эмбиент) — тогда состояние сцены — данные,
   а `UIDialogManager` — их отображение. *Кто: автор.*
5. **Переходы между блоками.** Предложение: метки = секции файла; `goto [Секция]` — без возврата,
   `call [Секция]` — с возвратом; только на начало секции. Цикл через `goto` допустим, если в нём
   есть ожидание игрока. *Кто: автор.*
6. **Синтаксис реплики.** Предложение: `Lucia.happy: текст до конца строки`; нужен параметр «текст
   до конца строки» и обозначение рассказчика. *Кто: автор.*
7. **ID реплик** для локализации и пропуска прочитанного. Предложение: импорт дописывает к строке
   короткий ID (`#a1f3`), перевод и «прочитано» — по ID. *Кто: автор.*
8. **Главный герой** — выбирает ли игрок имя и пол (документ дизайнера на это опирается)?
   *Кто: ГД.*

## Решено

2026-10-17:
- **Своя диалоговая система вместо Naninovel** ([[E12 Диалоговая система]]). Сценарии — тем же
  языком скриптов; персонажи — Spine или картинки; три слоя отображения (фон, персонажи,
  виджеты); `UIDialogManager` с `Get<TWidget>()`, команда не привязана 1:1 к виджету.
- **Единый контейнер переменных** на игру — для скриптов карт и диалогов
  ([[T052 Система игровых переменных]]).
- **Поправки к документу дизайнера:** изображения — из библиотеки по ID; бэклог — отдельное окно
  диалоговой системы; журнал и меню — общеигровой UI; звук — мгновенные + эмбиент по каналам.
- **Скрипты прототипа** выгружаются в текст сразу после раскладки по слоям ([[T051 Экспорт скриптов прототипа в текст]]).

2026-10-11, пятая часть:
- **Шаблоны команд** — атрибут `[Script(name, template)]`: `[Поле]` — параметр, `{Поле}` — блок
  (перенос строки и отступ), текст между блоками — продолжения (`else`); продолжение без
  параметров с пустым блоком не выводится.
- **Формат скриптов** — свой текстовый язык, источник правды. Язык = текст инспектора без
  управляющих элементов. Файл на карту, хуки секциями; общеигровые скрипты — отдельный файл с
  именованными хуками (кнопки UI и т.п.). Имена хуков — без пробелов, PascalCase.
- **ID.** У конфигов — строковые ID, у объектов внутри игры (экземпляры карт) — `int`.
- **Параллельность.** `Parallel` — запускает вложенные команды одновременно и ждёт всех.
  `Background` — запускает и не ждёт; запущенное отслеживается как отдельный скрипт.
- **Инспектор скриптов** — rich-текст, как редактор триггеров Warcraft 3: кликабельные `[...]`,
  перетаскивание строк, `[+]` / `[-]`.

2026-10-11, четвёртая часть:
- **Сохранения по слоям** — подтверждено: ядро в Core, секция на систему в Model, когда
  сохранять — `GameFlow` (Game), хранилища — интеграции.
- **Граница Core / Architecture.** Architecture — как связан код (DI, события, асинхронность,
  IO, твины), без понятий игры. Core — язык описания контента и логики.
- **Команды в любом слое** выше Core; конфиг хранит их, не зная типа. Для команд, которым нужна
  сцена, — лёгкая тестовая сцена.
- **Гибрид «слои + интеграции».** Основная логика — в слоях. Всё, что зависит от внешнего мира, —
  модули-интеграции (сборка на модуль), подключаются через DI в Game. Схема как у аналитики в
  GeekyHouse: ядро в Core → мосты в слое своей системы (класс на систему) → интеграции.
- **Аналитика** — нужна ([[E11 Аналитика]]).
- **Локализация** — в Core, нужна независимо от Naninovel.
- **Платформы** — ядро игровых сервисов в Core, интеграции под платформы отдельно
  ([[T049 Ядро игровых сервисов платформ]]). Хранилища сохранений — так же.
- **Настройки игры** — основа в Core, настройки — ScriptableObject, переопределения игрока рядом
  с сейвами или в PlayerPrefs ([[T048 Глобальные настройки игры]]).
- **Прототип** переносится в `Code/_Legacy/`.

2026-10-11, третья часть:
- **Команды:** база — Core, конкретные — Model.
- **Сборки:** одна на слой, папки `Code/<Слой>/` (включая `Code/Architecture/`). Не по сборке на
  модуль — внутри слоя возможны перекрёстные ссылки.
- **Слои** (крупные, сверху вниз): Game → Presentation / UI → Model → Core → Architecture.
  Зависимости только вниз; наверх — через интерфейсы нижнего слоя и события `EventBus`.
- **Слот вместо зоны.** Слот — место, на которое можно положить одну или несколько карт: и для
  выбора карт, и для инвентаря. Поле экспедиции — набор слотов; от жёсткой сетки планируем
  отказаться (решим при реализации).
- **Схемы зависимостей** — слои горизонтально, элементы в строку, вверх — пунктир.
- **Namespace** — только с телом `namespace X { ... }`.
- **Конфиги анимаций**: тип `AnimationProfile` — Architecture; наборы анимаций карт и слотов —
  Presentation; ассеты — `Content/Animations/` ([[E10 Процедурные анимации карт]]).

2026-10-11, вторая часть:
- **Описание игры** — [[Описание игры]].
- **Реакции карт** срабатывают сразу, вложенно: если с картой что-то сделали — она сразу реагирует.
- **Команды асинхронные.** Каждый командный скрипт завершается, вечных циклов нет. Сохраняться
  можно только когда нет ни одного активного скрипта. Игра строго пошаговая — это гарантирует
  моменты, когда скрипты завершились. Визуальную ленту анимаций не делаем — избыточно.
- **Выбор после розыгрыша** не нужен. Механики добора из колоды нет: рука — то, что игрок выбрал
  до экспедиции. Цель выбирается только перетаскиванием. Новая идея — подкрепления
  ([[T045 Подкрепление - второй герой во время экспедиции]]).
- **Конец хода.** Ход заканчивается, если герой перемещён на новую клетку; возврат на исходную
  клетку ход не заканчивает ([[T046 Возврат героя на исходную клетку не завершает ход]]).
  Пропуск хода — отдельное действие через UI ([[T047 Пропуск хода через UI]]).

2026-10-11:
- **Ресурсы.** Инвентарь — это колода. 15 собранных трав = 15 карт травы в колоде. Стаков нет.
- **Lua не используем.** Развиваем систему команд; как именно — обсуждаем в
  [[E04 Система команд]].
- **Анимации.** Пока играют анимации, с картами взаимодействовать нельзя, с UI — можно.
- **Реактивные свойства** — R3.
- **Приватные поля** — `m_Field`.
- **Платформы.** PC (Steam); вероятно Android, iOS и Web (itch.io). macOS не собираем.
- **Камера.** Текущее управление камерой устраивает — сохранить при переносе.
- **Не делаем:** туман войны, ранение героя при поражении, журнал.
- **Будет переделано:** визуал карт (редизайн), логика руки.
- **Визуальные новеллы.** Возможно своё решение вместо Naninovel — ждём требований (решено 2026-10-17: своё)
  ([[T043 Требования к системе визуальных новелл]]).
