## Общие принципы

Принципы — рекомендации, а не строгие правила. От них можно отступать, если выгода очевидна.

- **SRP** — один класс решает одну задачу. Задачей считается и управление другими классами.
- **DRY** — без повторяющегося кода. Одни и те же поля не дублируются в нескольких объектах:
  если нужны параметры из конфига — дайте доступ к конфигу.
- **KISS** — минимум сущностей для решения задачи, но с учётом будущих изменений.
- **YAGNI** — без оверинжиниринга и преждевременной оптимизации.
- Контент и логика — в разных классах. Много чисел в классе — повод вынести их в конфиг.
- Все классы — в namespace. Namespace — только с явным телом `namespace X { ... }`, без file-scoped.
- Класс больше 500 строк, метод больше 30 строк или с цикломатической сложностью выше 6,
  метод с более чем 4 аргументами — сигнал разделить.

## Форматирование

- Отступ — 4 пробела, не табы.
- Скобки — стиль Олмана (открывающая на новой строке).
- Однострочные тела `if`/`else` — без скобок, если короткие.
- Guard-if: если тело больше одного выражения — инвертировать условие и выйти раньше.
- Property patterns: `field is { IsNull: false }` вместо `field != null && !field.IsNull`.
  Unity 6 использует C# 9: только вложенная форма `a is { B: { C: true } }`, без `a.B.C`.
- `#region` / `#endregion` вместо комментариев-разделителей.
- Директивы (`#region`, `#if`, `#define`) — без отступа.
- Не заводить избыточные поля, если можно проверить null: `m_Parent != null` вместо `m_IsChild`.

## Именование

- Классы, структуры, интерфейсы, свойства, методы, события — `PascalCase`. Интерфейсы —
  с префиксом `I`.
- Приватные и защищённые поля — `m_PascalCase`.
- Константы — `UPPER_UNDERSCORE`.
- События — подлежащее + сказуемое: `Completed`, `CardMoved` (произошло), `CardMoving`
  (происходит, можно отреагировать до).
- Обработчики событий — префикс `Handle`: `Completed += HandleCompleted;`.
- Без сокращений, кроме общепринятых (`HUD`, `JSON`, `UI`, `VM`).

## Постфиксы классов

| Постфикс | Значение |
|---|---|
| `Manager` | управляет множеством объектов, единолично добавляет и удаляет |
| `Controller` | управляет одной сущностью и её связями с внешним миром |
| `System` | система сессии в модели (карты, слоты, сюжет) |
| `Service` | глобальный сервис (сохранения, сцены, звук) |
| `View` | отображение данных |
| `ViewModel` / `VM` | промежуточное звено MVVM |
| `Widget` | отображение с собственной логикой, касающейся только его самого |
| `Model` | конфиг, описывающий сущность (`CardModel`) |
| `Settings` / `Behaviour` | компонент сущности: настройка в конфиге / поведение в игре |
| `Save` | структура данных сохранения |
| `Action` | действие игрока |
| `Request` | запрос к `GameFlow` |
| `Converter`, `Wrapper`, `Bridge`, `Hierarchy`, `Holder`, `Factory` | как в GeekyHouse |

## Меню редактора

- Команды: `[TheGrowth]/<Система>/<Команда>`.
- Создание ассетов: `[Game]/...`.
