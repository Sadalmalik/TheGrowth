## Три вида данных

| Вид | Что это | Где живёт | Пример |
|---|---|---|---|
| Конфиги | неизменяемые настройки, которые делают дизайнеры | ScriptableObject в редакторе | карта «Монстр», локация «Лес», шаг сюжета |
| Состояние | всё, что меняется во время игры | системы сессии (обычные C# классы) | где лежит каждая карта, текущий шаг сюжета |
| Сохранение | снимок состояния для записи на диск | простые структуры с версией | `cards.json`, `slots.json` |

Правила:
- Игровые классы не знают о формате сохранения. Переименование класса не ломает сейвы игроков.
- В конфигах не хранится состояние игры.

## Конфиги и ID

- У каждого конфига, на который ссылаются сохранения или скрипты, есть строковый `Id`
  (например, `monster_1`), уникальный в пределах своего типа. Переименование ассета ID не меняет.
- Объекты внутри игры (экземпляры карт) получают числовой ID при создании.
- Все конфиги собраны в реестр контента. Проверка (меню и перед сборкой) находит дубли ID и
  битые ссылки.

## Системы сессии

Состоянием владеют системы. Каждая отвечает за своё и сама его сохраняет:

| Система | За что отвечает |
|---|---|
| Карты | все экземпляры карт |
| Зоны | где лежит каждая карта |
| Сюжет | текущий шаг, история шагов |
| Флаги | сюжетные переменные (общие с Naninovel) |
| Квесты | активные и завершённые квесты |
| Крафт | доступные крафты |
| Локации | текущая и открытые локации |
| Экспедиция | состояние текущей экспедиции |
| Случайность | генератор случайных чисел (чтобы загрузка давала тот же результат) |

## Сохранения

### По слоям

| Слой | Что делает |
|---|---|
| Core | ядро сохранений: API слотов (список, сохранить, загрузить, удалить), `SaveGame` (meta + секции), упаковка в zip, атомарная запись через интерфейс хранилища, `ISaveable`, миграции, ротация 3 автосейвов |
| Model | системы реализуют `ISaveable`, у каждой своя секция-DTO |
| Game | когда сохранять: `GameFlow.CanSave` (нет перехода, диалога, активных скриптов), автосейв по игровым событиям; загрузка = `CreateSession(save)` |
| UI | экран слотов через VM, список по `meta.json` |
| Integrations | хранилище: файлы (PC, мобильные), Web; облако Steam — по необходимости |

Настройки игрока хранятся отдельно от слотов.

### Формат

- Один слот — один zip-архив.
- Внутри: `meta.json` (дата, время в игре, шаг сюжета, локация, тип слота), по файлу на систему,
  превью-скриншот.
- Список слотов строится по `meta.json` без чтения остального.
- Запись атомарная: сначала во временный файл, потом замена. Сбой во время записи не портит
  старое сохранение.

### Слоты

- Ручные сохранения — без ограничения количества. В игре ветвящийся сюжет, игроку важно
  пробовать разные выборы без переигрывания всей игры.
- Автосейвы — 3 слота по кругу, перезаписывается самый старый.
- Сохранение возможно посреди экспедиции (между ходами), но не во время диалога.

### Версии и миграции

- У каждой секции сохранения своя версия.
- Изменился формат секции — пишется миграция «старая версия → новая». Старые сохранения игроков
  продолжают загружаться.
- Каждая миграция покрыта тестом на сохранении старой версии.

## Отличия от сохранений GeekyHouse

| GeekyHouse | TheGrowth |
|---|---|
| один глобальный сейв, загрузка один раз при старте | слоты, загрузка в любой момент из меню |
| файл на менеджер, запись по отдельности | один архив на слот, запись атомарная |
| флаги Dirty и SaveAllowed на каждом менеджере | сохранение только в разрешённые моменты, одна проверка на всю игру |
| версий нет | версия и миграции на каждую секцию |

## Naninovel

- Источник правды по сюжету — наша система сюжета и флагов.
- Naninovel читает и меняет их через свои команды.
- Внутри диалога сохраняться нельзя, поэтому состояние Naninovel в сейв не пишется.
