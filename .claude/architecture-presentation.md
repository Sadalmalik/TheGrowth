# TheGrowth — архитектура: отображение (3D, карты на сцене, UI)

Часть детальной спецификации. Короткая версия — `CLAUDE.md` в корне.
Статус: вижен согласован командой 2026-10-10, кода ещё нет.

## Вижен

- Игра полностью трёхмерная. Референс по ощущениям — Marvel Snap: хорошо анимированные карты,
  минималистичный интерфейс. Стилизация — карты Таро и гадальные карты.
- Хаб — 2.5D: объекты в основном рисованные (моделлеров нет, только художники), но расставлены
  в 3D → параллакс и глубина без 3D-моделей.
- Инвентари заменяются колодами, UI крафта — доской, на которую кладутся карты.
- Причина: в прототипе хаб — UI-сцена, экспедиция — 3D-сцена, у карт два типа вьюх
  (`UIItem` и `EntityCardView`). Теперь вьюха карты одна.
- UI минимизирован: меню, сохранения, HUD, подсказки, оверлей диалога.

## Карты и слоты на сцене

- `CardView` — один префаб для всех мест (хаб, крафт, экспедиция). Лицо/рубашка — материалы,
  в будущем возможен Spine для анимированных иллюстраций. Пул вьюх на location scope.
- `SlotView` — якорь слота на сцене (колода, слот доски крафта, клетка поля, рука). Знает ID слота
  и раскладку (стопка, веер руки, растягивание вдоль кривой). При загрузке локации презентер
  связывает `SlotView` со слотами модели по ID.
- Построение сцены из модели: при загрузке локации для каждой карты в слотах этой локации
  создаётся вьюха и ставится в позицию без анимации. Так же восстанавливается вид после загрузки
  сохранения.
- Процедурные анимации — см. раздел «Конфиги анимаций».

## Конфиги анимаций (процедурные анимации)

Модуль `ProceduralAnim` (из GeekyHouse, коммит `82ed47f`; сейчас в `Assets/_XandArt/Modules`, переносится в `Code/Architecture/`): `AnimationProfile` —
ScriptableObject с кривыми трансформаций (позиция по Безье, масштаб, поворот, цвет), строит
DOTween-твины. Где что лежит:

| Что | Слой | Примечание |
|---|---|---|
| `AnimationProfile` (тип и проигрывание) | Architecture | не знает об игре |
| Ассеты профилей | `Content/Animations/` | |
| Набор анимаций карты (`CardAnimationSet`) | Presentation | ссылки на профили именованными полями |
| Анимации раскладки слота (сортировка колоды, растягивание вдоль кривой) | Presentation | настройки `SlotView` |
| Особая анимация конкретной карты (если понадобится) | Presentation | компонент в списке компонентов `CardModel`: Model объявляет интерфейс, Presentation реализует, Model тип не знает |

Анимации карт, которые нужно настроить: появление/исчезновение (масштаб из/в 0); перемещение в
слот (перетаскивание, телепорт, раздача из колоды); баунс при приземлении; зум при осмотре;
лёгкое «плавание» карт не на поверхности (смена угла для параллакса внутри карты-портала);
перемещение в колоду; сортировка колоды; растягивание колоды вдоль кривой (просмотр инвентаря).

Перед подключением: перенести модуль в `Code/Architecture/` (сейчас без asmdef код попадает в
Assembly-CSharp, на который asmdef-сборки ссылаться не могут); убрать enum `AnimationSlots` с ключами мержа GeekyHouse —
профиль не должен знать, где используется; убрать Odin. Задача — эпик E10.

## Анимации

- Асинхронные команды ждут анимаций вьюх (см. architecture-logic.md). Длительности и кривые —
  конфиг анимаций.
- Пока выполняются скрипты и анимации, взаимодействие с картами заблокировано; UI доступен.
- Отмена location scope останавливает активные скрипты и анимации. DOTween-твины привязываются
  к токену scope.

## Взаимодействие

- `CardInteractionController` (location scope) — единый для хаба и экспедиции: наведение,
  подъём, перетаскивание, подсветка допустимых слотов (`AllowedMoves`), бросок на слот.
- Результат взаимодействия — действие игрока (перемещение героя, применение способности, крафт).
  Контроллер не меняет модель напрямую.
- Раздельные кнопки: отмена перетаскивания и управление камерой не на одной клавише
  (в прототипе ПКМ делает и то, и другое).
- Ввод — через `InputService` (глобальный scope), который умеет блокироваться (`Block(owner)`).
  Пакет Input System, режим `Both`, пока прототип и камера на старом `Input` (решено 2026-10-20).
- Геймпад на поле (решено 2026-10-20): левый стик — выбор среди карт, которые можно
  перетащить (герой на локации, карты в руке), выбранная подсвечивается; кнопка выбора —
  карта поднимается; правый стик — движение карты над полем; повторное нажатие — попытка
  положить в место под картой: можно — карта кладётся, ход завершается; нельзя — карта
  возвращается, ход не завершается.

## Камера и хаб

- Хаб — 3D-сцена с «комнатами» (позиции камеры / подсцены). Переход между комнатами —
  перемещение камеры, не смена сцены.
- Объекты хаба (персонажи, доска крафта, колоды) — интерактивные объекты на сцене; клик →
  действие игрока или запрос `GameFlow`.
- Cinemachine — кандидат для переходов камеры и параллакса (не решено).

## UI (MVVM)

Подход — как в Owlcat: чистое разделение Model — View — ViewModel, реактивные свойства, без
reflection-биндингов по строкам (как `MemberBinding` в GeekyHouse). Пишем свою минимальную
реализацию, код Owlcat не копируем.

- Библиотеки: **R3** + **ObservableCollections** (Cysharp). Решено 2026-10-11 (UniRx архивирован,
  R3 — преемник).
- `ViewModel` — обычный C# класс, `IDisposable`, владеет своими подписками. Получает зависимости
  в конструкторе (системы сессии), не через статику. Свойства — либо вычисляемые (читаются из
  модели), либо `ReactiveProperty`; коллекции — `ObservableList` и т.п.
- `View<TViewModel>` — `MonoBehaviour`: `Bind(vm)` → `OnBind()` (подписки с `.AddTo(this)`),
  `Unbind()` освобождает подписки. Вьюха не меняет модель — вызывает методы VM, VM вызывает
  действия/запросы.
- Списки — хелпер «коллекция VM → список виджетов» с пулом.
- `UIManager` (глобальный scope) управляет слоями: `MainMenu`, `SaveLoad`, `Pause`, `Hud`,
  `Dialogue`, `Loading`, `Tooltip`, `Notifications`. Набор активных слоёв определяется
  `FlowState` и оверлеями `GameFlow`.
- Инициализация: слои и их VM создаёт `UIManager`. `WidgetBase`, `FindObjectsOfType` и инжект в
  `Awake` удаляются.

### Решено 2026-10-20

- **База MVVM — в Architecture** (`Code/Architecture/MVVM/`): `View<T>`, `ViewModel`, наборы
  подписок (`AddTo(view)` снимается при отвязке, `AddTo(vm)` — при `Dispose` VM), автоотвязка
  вьюхи при уничтожении VM, `WidgetList` (коллекция → виджеты из пула). R3 и ObservableCollections —
  зависимости Architecture. Вьюху можно привязать и не к VM, а к любым данным.
- **Окно существует ⇔ существует его VM**: открыть окно = создать VM, закрыть = `Dispose`.
  Корневая VM — свойство `ReactiveProperty<XxxVM>` на слой; подписки на свойства — явным списком,
  без рефлексии.
- **Префаб на слой**, создаётся фабрикой по требованию: таблица «тип VM → префаб», пул.
- **Наблюдатели по областям жизни**: глобальный (меню, загрузка, модальные подтверждения) и
  сессионный (HUD, пауза, сохранение). Сессионный регистрируется в контейнере сессии через
  `configure` из Game и уничтожается вместе с ней. Зависимости — инжектом, без сервис-локатора.
- **Данные**: события `EventBus` → `ReactiveProperty` в VM. Модель от R3 не зависит.
- Модальные окна блокируют игровой ввод (`InputService.Block`).
- **Навигация геймпадом** закладывается в базовые контролы.
- **Всплывающие окна** (модальные сообщения с кнопками) — часть UI-системы. Ошибки, которые
  должен увидеть игрок, показываются ими: например, загрузка слота более новой версии —
  «Невозможно загрузиться! Сохранение имеет более высокую версию, чем клиент.», затем главное меню.
- **uGUI + TextMeshPro**, анимации показа и скрытия — DOTween.
- **Вьюхи карт — не UI**: 3D-объекты, возможно целиком на Spine или только портрет на Spine;
  кастомные шейдеры обязательны. MVVM для вьюх карт не используется.

### Реализация (T067, 2026-10-20)

Код: `Code/Architecture/MVVM/`, `Code/UI/` (`Root/`, `Flow/`, `Popups/`, `Loading/`, `MainMenu/`,
`Pause/`, `Saves/`, `Observers/`, `Texts/`, `Controls/`), `Code/Game/UI/UIFlowAdapter.cs`,
`Code/Editor/UI/UIPrefabBuilder.cs`. Префабы — `Prefabs/UI/`, таблица — `Content/UI/UIViewConfig.asset`.
Пересборка префабов и UI сцены `Main` — меню `[TheGrowth]/Flow/Rebuild Main UI` (перезаписывает префабы).

- Architecture: `ViewModel` (набор подписок, токен `Lifetime`, событие `Disposing`), `ViewBase` /
  `View<T>`, `AddTo(view)` / `AddTo(vm)`, `Open` / `Close` для свойств окон, `ViewPool<T>`,
  `WidgetList<TData, TView>` (по событиям `IReadOnlyObservableList`), `EventBusObservable.Observe<T>()`.
- Стык UI ↔ Game: `IUIFlow` (UI) — состояние `ReadOnlyReactiveProperty<UIFlowState>`, `CanSave`,
  `NewGame`, `Load(slot)`, `SaveAsync(slot | null)`, `ExitToMenu`, `Quit`; реализация — `UIFlowAdapter`
  (Game), действия → запросы `GameFlow`. Список слотов и превью UI читает из `SaveService` напрямую.
- Корень: `UIRootViewModel` — `ReactiveProperty` на слой; `UIManager` подписан явным списком,
  события `Opened` / `Closed`. `UIRootView` берёт вьюху из фабрики по типу VM (с базовыми типами);
  тип VM задаёт сам префаб (`ViewBase.SourceType`) — таблица хранит просто список префабов.
- Закрытие окна — `vm.Close()` / `Dispose`; дочерние окна (слоты из меню или паузы) уничтожаются
  вместе с родительским.
- Слои снизу вверх: MainMenu, Pause, SaveLoad, Popup, Loading. Модальны Pause, SaveLoad, Popup
  (`InputService.Block(vm)`).
- Фокус: мышь и навигация — только у верхнего окна (`CanvasGroup.interactable`); окно запоминает
  выбранный элемент и получает его обратно, когда снова становится верхним; во время экрана
  загрузки ввод UI не обрабатывается. Назад — Esc / B, пауза — Esc / Start (`InputAction` в
  `UIRootView`; без открытого окна — `PauseRequested`, обрабатывает `SessionUIObserver`).
- Всплывающие окна — очередь в `PopupService`; закрытие без выбора = кнопка отмены, фокус по
  умолчанию на ней. Ошибки загрузки, перезаписи и удаления слота — всплывающим окном,
  текст — `UITexts.LoadFailed(kind)`.
- Анимации окон — DOTween, альфа `CanvasGroup`, время без масштаба, прерываемые; экран загрузки
  появляется сразу, скрывается за 0,3 с.
- Тексты — ключи в префабах (`UIStaticText`) и таблица `UITexts` (до локализации, T039).
  Шрифт UI — статический `Fonts/CormorantGaramond UI SDF.asset` (2026-10-20): атлас 1024×1024, 72 pt,
  латиница, кириллица, знаки; при игре не меняется. Пересборка — `[TheGrowth]/UI/Rebuild UI Font`
  (новый GUID → затем `Rebuild Main UI`). Динамический Cormorant остаётся у префабов прототипа.
- `GameFlow.IsPaused` пауза не выставляет — системы паузы пока нет.
