# TheGrowth — архитектура: исполнение логики

Часть детальной спецификации. Короткая версия — `CLAUDE.md` в корне. Описание игры —
`.docs/Описание игры.md`. Открытые вопросы — `.docs/Вопросы.md`.

## Решения (2026-10-11)

- **Команды асинхронные.** Продолжительное действие (перемещение, переворот, диалог)
  ожидается, следующая команда выполняется после его завершения. Это то, ради чего в прототипе
  был заведён `AfterCommands`.
- **Реакции карт срабатывают сразу, вложенно**: если с картой что-то сделали, она сразу реагирует.
- **Каждый командный скрипт завершается**, вечных циклов в системе команд нет.
- **Сохраняться можно только когда нет ни одного активного скрипта.**
- **Игра строго пошаговая** (ход героя → ходы монстров) — это гарантирует моменты, когда все
  скрипты завершились.
- Визуальную ленту (отделение анимаций от логики) не делаем — избыточно.
- Цель действия выбирается только перетаскиванием. Выбора игрока посреди скрипта нет.
- Пока выполняются скрипты и анимации, с картами взаимодействовать нельзя; с UI — можно.

## Открыто

- Параллельность в асинхронных командах (замена веток `AfterCommands`) — обсуждается в эпике E04.

## Проблемы прототипа, которые нужно учесть

- `FlipCard` вызывает `onComplete` дважды при наличии вьюхи (`CardBrain.cs:91`).
- Без вьюхи путь логики другой и падает (`BoardUtils.MoveTo`, ветка `view == null`).
- `Task.Delay`-цепочки не отменяются при выходе из локации; асинхронные скрипты должны брать
  токен отмены своего scope (см. architecture-flow.md).
