# TheGrowth — архитектура: диалоговая система

Часть детальной спецификации. Короткая версия — `CLAUDE.md` в корне. Требования дизайнера —
`.claude/docs/Диалоговая система.md` (с поправками ниже). Открытые вопросы — `.docs/Вопросы.md`.

## Решения (2026-10-17)

- **Своя диалоговая система вместо Naninovel.** Причины: Naninovel — самостоятельный движок,
  интеграция трудная, настройка его UI неочевидна, совместить с UI и визуалом игры крайне сложно.
- **Сценарии — тем же языком скриптов**: команды диалогов задаются `[Script(name, template)]`,
  как геймплейные.
- **Персонажи** — Spine или картинки.
- **Единый контейнер дизайнерских переменных** на игру — общий для скриптов карт и диалогов.
  Синхронизации переменных между системами нет. Отдельная задача — T052.
- **Описание и отображение разделены**: скрипт — команды; отображение — виджеты. Соответствия
  1:1 команда ↔ виджет нет: команда работает с одним или несколькими виджетами.
- `UIDialogManager`: методы для фона и персонажей + `Get<TWidget>()` для виджетов.
- Скрытое ветвление (игроку ничего не показывается) — обычный `if` по переменным.
- Изображения — библиотека в конфиге, команда ссылается на изображение по ID.
- Звук: мгновенные звуки + эмбиент по номерным каналам (1, 2, 3, ...).

## Сценарий (решено 2026-10-17)

```
Start:
    Lucia.happy: Ты пришла!
    choice "Что спросить?"
        option "Про амулет" if [$trust_lucia > 3]
            call AboutAmulet
        option "Уйти"
            goto Farewell
    goto Start

AboutAmulet:
    Lucia: Его носила моя мать.

Farewell:
    Lucia.sad: До встречи.
```

- **Реплика** — короткая форма: `Персонаж.эмоция: текст до конца строки`, `Персонаж: текст` —
  эмоция не меняется. Рассказчик — явный персонаж по умолчанию `Narrator`. В шаблонах нужен
  параметр «текст до конца строки».
- **Метки** — секции файла. `goto Секция` — переход без возврата, `call Секция]` — с возвратом,
  в другой файл — `goto файл.Секция`. Переход только на начало секции.
- **Выбор** — `choice` с блоком команд-вариантов: `option "Текст"` с телом,
  `option "Текст" if [условие]` с телом; вариант по условию скрытый или неактивный.
- **Ввод текста** — виджет диалогового UI (имя игрока, имя питомца, название бара — может
  использоваться несколько раз), результат — в переменную.
- Игрок выбирает имя и пол главного героя.

- **Граница диалога — файл.** Файл диалога (своё расширение, отличное от скриптов карт) целиком —
  диалог: экран диалога открывается при входе в файл и закрывается, когда диалог закончился
  (секция кончилась без перехода или явная команда `end`). Игровые скрипты запускают диалог
  командой `dialog файл.Секция`. Эта команда **не ждёт** конца диалога (решено 2026-10-17):
  диалог запускается отдельно, как `Background`. Действия после диалога — в самом файле диалога
  или в реакции на событие «диалог завершён» (T031). Поэтому сохраняться можно в любом диалоге. `goto` / `call` из диалога ведут в секции файлов диалогов.
  Временно убрать UI внутри диалога — `hide ui` / `show ui`.
- **Где какие команды разрешены** (проверяется статически по типу файла):

| Контекст | Команды |
|---|---|
| везде | `if`, `goto` / `call`, переменные, инвентарь (в диалоге могут выдать карту) |
| только в диалогах | реплики, выборы, ввод текста, операции с фоном, персонажами и виджетами диалога |
| только вне диалогов | перемещение карт по слотам, их анимации и т.п. |

## Локализация реплик (решено 2026-10-17)

- ID у каждого видимого игроку текста: реплики, текст выбора и вариантов, подсказки ввода —
  отдельный тип параметра «локализуемый текст».
- ID — случайный, не менее 6 символов, уникален внутри файла; пишется в конце строки:
  `Lucia: Wha... HOW? #k3f9a2`. В инспекторе ID скрыт.
- Ключ локализации = ID файла (один раз в заголовке файла) + ID строки.
- ID новым строкам назначаются при разборе; файл пересохраняется сразу после импорта (не внутри
  импорта), один раз.
- Текст исходного языка всегда берётся из сценария; таблицы локализации — только для переводов.
  У строки перевода хранится отпечаток исходного текста; изменился исходник — перевод
  помечается устаревшим.
- Подстановки (`{PlayerName}`) и формы по роду — в конце, на полишинге (T053).

## Сохранение в диалоге (решено 2026-10-17)

- Команда реплики ставит виджету задачу «вывести текст» и ждёт его: пока виджет выводит текст,
  скрипт уже в ожидании.
- Сохранять можно, когда диалог ждёт игрока: реплика выведена и ждёт «далее», открыт выбор или
  ввод текста. «Далее» — клик в любом месте экрана, кроме прочих кнопок (кликабельная область под
  всеми виджетами, виджеты по умолчанию прозрачны для кликов).
- Сохраняется позиция исполнения (файл, секция, путь внутри блоков, стек `call`) и состояние сцены
  (фон, персонажи, эмбиент) — состояние сцены диалога является данными.
- Команда `autosave` — для сохранения перед особенно важными выборами (не перед каждым: сейвов
  будет слишком много).

### Что сохраняется и как загружается (решено 2026-10-17)

`ScriptRunner` не сохраняет произвольные скрипты: в момент сохранения игровые скрипты завершены,
активен может быть только диалог, ждущий игрока. Его сохраняет диалоговая система своей секцией.

- **Позиция:** ID файла, стек кадров (секция + путь индексов внутри блоков, стек `call`),
  ID ожидающей строки.
- **Состояние сцены (`DialogStage`, данные):** фон (изображение, трансформ, цвет), персонажи
  (ID, эмоция, позиция, видимость), эмбиент по каналам. Команды диалога меняют `DialogStage`,
  `UIDialogManager` её отображает и анимирует переходы (ожидание — через интерфейс, как
  `ICardAnimator`).
- Виджеты не сохраняются — их восстанавливает повторное выполнение команды ожидания.
- Переменные сохраняет своя система (T052).

Загрузка: сессия создана, системы прочитаны → если диалог был активен, открывается экран диалога,
сцена выставляется без анимаций → `ScriptRunner` восстанавливает стек кадров → команда ожидания
выполняется заново в режиме восстановления (реплика — сразу целиком, выбор — сразу открытым) →
скрипт идёт дальше.

Правки сценария после релиза: вместе с путём хранится ID ожидающей строки. При загрузке строка по
пути проверяется по ID; не совпала — поиск по ID в файле (уникален внутри файла); не найдена —
начало секции.

## Отображение: три слоя

| Слой | Возможности |
|---|---|
| Фон | включить / переключить / выключить (мгновенно или через фейд); выключен — диалог идёт поверх игры; цвет, прозрачность; размер, масштаб; сдвиг (фон больше экрана — «перемещение по комнатам»); эффекты (тряска) |
| Персонажи | картинка или Spine; добавить / убрать (мгновенно, фейд, выезд из-за края); перемещение, масштаб; эмоция, анимация; говорящий по умолчанию чуть крупнее и светлее; расстановка по умолчанию: сторона экрана (Left/Right), персонажи одной стороны — в линию с заданным шагом |
| Виджеты (расширяемый) | реплика: персонаж, эмоция, текст с форматированием, посимвольный вывод; выбор: вопрос и варианты, вариант может быть неактивным или скрытым по условию; информационные: квестовые предметы, доверие персонажа и т.п. |

## Поправки к документу дизайнера

- «Загрузка изображений» не нужна: изображения берутся из библиотеки по ID.
- Бэклог (прокручиваемая история реплик) — часть диалоговой системы, но отдельное окно, не виджет.
- Журнал (квесты, известные факты, персонажи и места) — отдельный экран UI, не диалоговая система.
- Меню (выход, сохранение и загрузка, скрыть UI) — общеигровой UI.
- Переменные — отдельная система (T052).
