# TheGrowth — архитектура: скрипты (команды, кондишены, эвалуаторы)

Часть детальной спецификации. Короткая версия — `CLAUDE.md` в корне.
Модель исполнения — [architecture-logic.md](architecture-logic.md).

## Решения (2026-10-11)

- Скрипты настраивают все (дизайнеры и программист). Lua не используем, C# для логики карт не
  пишем. **Развиваем систему команд.**
- Доработка системы команд обсуждается в эпике E04 (`.docs/tasks/E04 Система команд.md`).
  Решено: `Parallel`, `Background` (см. architecture-logic.md), инспектор rich-текстом, хранение —
  свой текстовый язык (ниже).
- **Уход с Odin** обязателен.

## Инспектор скриптов (вижен автора, 2026-10-11)

Скрипт рисуется не деревом полей, а многострочным rich-текстом, как редактор триггеров
Warcraft 3:

```
= if [charge > 1] and [[distance between [hero] and [target]] < 5] [+]
=   Log ["We are near target"] [-]
=   AddBuff [BuffEvaluator options] to [HeroCardEvaluator]
=   [+]
= else
=   Log ["We are too far"] [-]
=   [+]
= [+]
```

- `[...]` — кликабельный элемент: открывает небольшую панель редактирования (значение,
  переменная, вложенный эвалуатор).
- `=` — перетаскивание строки: весь скрипт — один список строк.
- `[+]` — добавить команду в блок, `[-]` — удалить команду.
- Сложные условия можно переносить на несколько строк.
- Цель — убрать визуальный шум инспектора; в связке с ИИ-агентом дизайнер описывает задачу
  словами, агент собирает скрипт.

## Формат хранения скриптов (решено 2026-10-11)

**Свой текстовый язык — источник правды.** Язык — это текст, который рисует инспектор, без
управляющих элементов (`=`, `[+]`, `[-]`, кликабельность — только в инспекторе, в файле их нет).

- Шаблон отображения команды задаётся атрибутом на классе (`Log [message]`,
  `Move [card] to [slot]`). Ключевые слова — из атрибутов, не имена классов: переименование
  класса скрипты не ломает.
- Аргументы в `[...]` — разбор однозначный: литеральные слова шаблона определяют команду, скобки —
  границы аргументов. Валидатор проверяет, что «скелеты» шаблонов не совпадают.
- Блоки — отступами, как в инспекторе.
- Ссылки на конфиги — по строковому ID.
- Хуки — именованные секции, имена — идентификаторы без пробелов, PascalCase (как события в C#):
  `OnPlaced`, `OnStep`, `OnCovered`, ...
- **Файл на карту**: логика карты — один файл рядом с ассетом карты, хуки карты — секциями.
- **Общеигровые скрипты** — отдельный файл (или несколько) с именованными хуками под точки в игре:
  кнопки UI, триггеры. Объект сцены ссылается на хук по имени (выпадающий список в инспекторе).
  Валидатор проверяет, что все ссылки на хуки существуют.
- Импортёр (`ScriptedImporter`) разбирает файл при импорте, ошибки — с номером строки.
- Расширения: `.script` и `.dialog` (см. «Синтаксис языка»).

```
OnPlaced:
    if [charge > 1] and [[distance between [hero] and [target]] < 5]
        log "We are near target"
        AddBuff poison to [hero]
    else
        log "We are too far"

OnStep:
    Parallel
        Move [active card] to [nearest free slot]
        Flip [card under [active card]]
```

### Шаблоны команд: атрибут `[Script]` (решено 2026-10-11)

Имя и синтаксис команды (кондишена, эвалуатора) задаются атрибутом на классе. Имя класса ни на что
не влияет — переименование не ломает скрипты.

```csharp
[Script("if", "if [Condition] {OnTrue} else {OnFalse}")]
public class Branch : Command
{
    public Condition Condition = new And();
    public List<Command> OnTrue = new List<Command>();
    public List<Command> OnFalse = new List<Command>();
}

[Script("log", "log [Message]")]
public class DebugLog : Command
{
    public string Message;
}
```

- Первый аргумент — имя: стабильный ключ для списка команд в инспекторе, каталога для ИИ и
  документации.
- `[Field]` — параметр; в тексте кликабелен.
- `{Field}` — список вложенных команд (блок). `{}`, а не `<>`: угловые скобки конфликтуют со
  сравнениями в шаблонах (`[A] < [B]`).
- Обе скобки существуют только в шаблонах. В файле блоков не видно — только отступы.

Многострочные команды:
- Маркер блока всегда означает перенос строки, блок с отступом, снова перенос.
- Текст до первого блока — заголовок; текст между блоками — строки-продолжения на отступе
  заголовка (`else`); текст после последнего блока — замыкающая строка
  (`repeat {Body} until [Condition]`).
- Пропуски: продолжение без параметров с пустым блоком не выводится (`if` без `else`). Инспектор
  показывает скрытую секцию кнопкой (`[+ else]`).
- Разбор: строка на том же отступе, совпадающая с текстом продолжения, относится к предыдущей
  команде; не совпадает — секция пустая.

```
if [charge > 1]
    log "near"
else
    log "far"
```

Валидатор при запуске:
- имена уникальны;
- «скелеты» шаблонов (литеральные слова + места параметров) не совпадают;
- слова продолжений (`else`) не начинают ни одну другую команду;
- поля из `[..]` и `{..}` существуют, `{..}` — список команд.

Открыто (`.docs/Вопросы.md`): повторяющиеся секции (`else if`); скобки у литералов внутри
вложенного узла.

### Синтаксис языка (решено 2026-10-17)

- **Файлы:** `.script` — скрипты карт и общеигровые хуки, `.dialog` — диалоги. UTF-8.
- **Секции:** строка с нулевым отступом вида `Имя:`, после двоеточия ничего нет. Всё содержимое
  секции — с отступом. Реплика `Lucia: текст` всегда внутри секции, поэтому с заголовком не путается.
- **Свойства-выражения** (в файле карты): строка с нулевым отступом `Имя -> [выражение]`, например
  `AllowedMoves -> [slots around [active card] cross 1]` (решено 2026-10-17; реализация — T059).
- **Отступы:** парсер принимает любую постоянную ширину (блок глубже родителя и одинаков внутри
  себя), табуляция — ошибка. Принтер пишет 4 пробела — ширина задаётся одной константой.
- **Скобки — только вокруг вложенных узлов** (эвалуаторов, условий). Литералы — без скобок:
  числа, строки в кавычках, `true` / `false`, значения enum, ID конфигов, ссылки на секции,
  переменные `$имя`. Литерал в параметре типа `Evaluator<T>` оборачивается в константу.
  Приоритета операций нет: `[[$a + 1] > 3]`. Кликабельность в инспекторе от скобок не зависит.

```
if [$trust_lucia > 3]
    add 5 to $coins
    move [active card] to [nearest free slot]
    log "We are near target"
```

- **Списки** в параметре — элементы через запятую.
- **Текст до конца строки:** `[Field...]` в шаблоне — только последний параметр строки, забирает
  остаток строки до ID `#xxxxxx`, если он есть.
- **Несколько шаблонов у класса:** `[Script]` можно повесить несколько раз (`Lucia: текст` и
  `Lucia.happy: текст` — один класс). Принтер выбирает самый подробный шаблон, у которого
  заполнены все параметры.
- **Комментарии:** строка `// ...` — пустая команда в дереве, переживает пересохранение. В конце
  строки после кода комментариев нет.
- **`else if`** — вложенный `if` внутри `else`.
- Ошибки разбора собираются по всему файлу, с номерами строк.
- Принтер — канонический формат (пустая строка между секциями). Тест на каждую команду:
  печать → разбор → печать даёт тот же текст.

### Реализация (T056, `Code/Core/Scripting/Registry`, `Language`, `Text`)

- `ScriptRegistry` (не статический) собирает классы с `[Script]`, проверяет шаблоны и при ошибках
  бросает одно исключение со списком всех проблем. Тестовые сборки в общий реестр не попадают.
- `ScriptParser` / `ScriptPrinter`; ширина отступа — `ScriptSyntax.IndentWidth`.
- `LineId` — свойство команды (как `Location`), только на первой строке команды.
- Незаданный параметр печатается как `[]` — такой текст не разбирается, место видно сразу.
- `$имя` и `[узел].имя` — в параметрах-узлах (`Condition`, `Evaluator<T>`, `Value`) и в параметре-
  переменной (запись, T052).
- Комментарий с нулевым отступом — ошибка.
- Ограничения на имена: ID файла скриптов — идентификатор (без пробелов, не с цифры), иначе на него
  нельзя сослаться; ID персонажа не должен совпадать с ключевым словом команды (иначе реплика
  `Имя: текст` неоднозначна). Проверяет валидатор.
- Импортёр `.script` / `.dialog` (`Code/Editor/Scripting/`): ID конфигов — по реестру контента
  (переимпорт при изменении набора ID через зависимость `TheGrowth/ContentIds`); без реестра —
  разрешающая заглушка с предупреждением. Переменные — заглушка до T052.
- Параметр-конфиг команды — наследник `ContentAsset`.
- `ScriptLanguage` — глобальный сервис с реестром команд; `ContentScriptLibrary` — система
  сессии, разбирает файлы скриптов по запросу и кеширует на сессию (T060).
- Доработки — T059.

### Переменные в языке (T052, 2026-10-21)

- Виды параметров шаблона: `Variable` — цель записи (поле — тип, реализующий `IVariableTarget`;
  формы `$имя` и `[узел].имя` без пробелов вокруг точки); `Value` — значение любого типа (поле
  `IEvaluator`), тип берётся от другого параметра той же строки (`[ScriptTypeOf(nameof(A))]`),
  разбирается вторым проходом; `Owner` — узел владельца переменных.
- `IScriptVariableResolver`: `OwnerType`, `TryResolve(name, owner, type, …)`,
  `TryGetReference(value, out name, out owner)`. Реализация — `VariableScriptResolver`.
- Узлы без шаблона: `$имя` / `[узел].имя` → `VariableValue<T>`, `VariableCondition` (bool в
  условии), `VariableReference<T>` (запись). Узел владельца вычисляется при каждом обращении.
- Команды и узлы Core (`Code/Core/Scripting/Expressions/`, `Code/Core/Variables/`):
  `set [Variable] to [Value]` (любой тип), `add [Amount] to [Variable]` (int),
  `[A] [Operator] [B]` (`compare`: `>` `<` `>=` `<=`, int), `[A] == [B]` / `[A] != [B]`
  (int, bool, string; тип B — как у A), `not [Condition]`, `[A] and [B]`, `[A] or [B]`,
  `[A] + [B]` / `[A] - [B]` (int, переполнение — ошибка исполнения).
- Условие там, где ждут bool (2026-10-21): в параметр `Evaluator<bool>` и в значение bool
  (`set $flag to [$a > 3]`) подходят шаблоны условий — парсер оборачивает условие во встроенный
  `ConditionValue`, принтер печатает само условие. Поэтому условие и эвалуатор bool не могут иметь
  одинаковый скелет шаблона (проверка реестра).

### Скрипты карт (решено 2026-11-04, T074)

- Файл карты — `<имя конфига>.script` в папке конфига `EntityModel`; привязка автоматическая
  (`ContentRegistryBuilder.Rebuild` записывает ID файла в конфиг). Файл может быть у сущности любого
  вида; хуки пока вызываются только у карт.
- Свойства `Имя -> [выражение]` — только в файлах сущностей; набор свойств и их типы задаются в коде:
  `AllowedMoves`, `SpawnSlot` — набор слотов. Вычисляются по запросу, `[active card]` — карта.
- Хуки — секции файла карты: `OnPlacedFirstTime`, `OnPlaced`, `OnFlipped`, `OnStep`, `OnCovered`,
  `OnUnCovered`. Секции нет — ничего не происходит. Хук внутри скрипта — вложенный запуск того же
  исполнения; вне скрипта — новый запуск `ScriptRunner`.
- Хуки размещения — только в слотах с `SlotRules.InvokePlaceEvent` (клетки поля — да; инвентарь,
  колода, рука, сброс, рюкзак — нет):
  - `OnUnCovered` — у карты, которая стала верхней, когда верхнюю карту убрали; флаг — у слота-источника;
  - `OnCovered` — у прежней верхней карты, когда на неё легла карта; флаг — у слота-цели;
  - `OnPlaced` — у положенной карты; флаг — у слота-цели;
  - порядок — `OnUnCovered` → `OnCovered` → `OnPlaced` (как в прототипе); `[covering card]` — карта,
    которая накрыла или ушла;
  - `SlotSystem.Move` синхронный и хуков не вызывает; хуки вызывают команды (`move`, `create`,
    `destroy`); раскладка двигает карты через `SlotSystem` без хуков.
- `OnFlipped` — после смены стороны карты командой.
- Близость — по графу поля: `within N` — слоты в пределах N связей (без своего); `nearest` — по числу
  шагов, при равенстве — по геометрии, затем по порядку набора. Объекты механики на связях пока не
  учитываются (шаг 8 E03). По геометрии — фигуры: `slots in [Shape] around [Card]` (T075, «Фигуры»).
- Наборы упорядочены (порядок слотов графа); `except`, `or`, `and` сохраняют порядок левого операнда.
  Одиночный слот или карта там, где ждут набор, — набор из одного элемента.
- Пустое значение (решено 2026-11-04): эвалуатор не нашёл карту или слот — результат
  пустой; команда с пустой картой или слотом ничего не делает, условие на пустом — false, проверка —
  `exists`.
- `[hero]` — карта героя экспедиции: явная ссылка в состоянии экспедиции (`SlotSystem.SetHero`, ставит раскладка,
  шаг 5 E03), без перебора поля; хранится в сейве (решено 2026-11-04). Тег `Hero` героем карту не делает.
- `random` и `chance` — с ГСЧ сессии (`RngSystem`, T072): состояние в сейве, после загрузки те же действия дают тот же
  результат.

#### Базовый набор узлов (T074)

Тег-параметр — литерал без кавычек, проверяется по реестру тегов при разборе. Одиночная карта или слот там, где ждут
набор, — набор из одного (принтер печатает исходный узел).

| Вид | Шаблоны |
|---|---|
| карта | `active card`, `covering card`, `iterating card`, `hero`, `card under [Card]`, `top card of [Slot]`, `random card of [Cards]` |
| набор карт | `cards in [Slots]`, `cards tagged [Tag]` (на поле), `[A] except [B]`, `[A] or [B]`, `[A] and [B]` |
| слот | `slot of [Card]`, `deck`, `hand`, `discard`, `backpack`, `inventory`, `nearest of [Slots] to [Card]`, `random slot of [Slots]` |
| набор слотов | `field slots`, `free slots`, `slots tagged [Tag]`, `slots around [Card] within [Distance]`, `slots of [Cards]`, `[A] except [B]`, `[A] or [B]`, `[A] and [B]`, `slots in [Shape] around [Card]` (T075) |
| число | `count of [Cards]`, `count of slots in [Slots]`, `random number from [A] to [B]` |
| условие | `[Target] has tag [Tag]` (карта или слот), `[Slot] is empty`, `[Slot] is full` (T075), `[Value] exists` (карта или слот), `==` / `!=` (карты, слоты), `chance [Percent]%` |
| команда | `move [Card] to [Slot]`, `flip [Card]`, `reveal [Card]`, `hide [Card]`, `destroy [Card]`, `create [Model] in [Slot]` (`[ModelKind(Card)]`), `for each card in [Cards]` + блок |

Отличия от предложения задачи:
- `count of slots in [Slots]` вместо `count of [Slots]`: скелет `count of []` с результатом int совпал бы с
  `count of [Cards]`.
- `has tag` и `exists` — по одному шаблону на карту и слот (параметр-значение с ограничением типа результата): два
  шаблона `[] has tag []` совпали бы скелетом.
- Контекст: `move`, `flip`, `reveal`, `hide` — только вне диалогов; `create`, `destroy`, `for each card` — везде (в
  диалоге могут выдать карту в инвентарь).
- `hero` — `ExpeditionSlots.Hero`; героя нет — пусто. Сбрасывается при уничтожении карты, перемещении её из слотов
  экспедиции и вместе с экспедицией.
- `cards tagged [Tag]` — все карты с тегом на поле, а не только верхние (в прототипе — `OnTop`). Поэтому клетка, где
  монстр или препятствие лежит под другой картой, тоже исключается из ходов героя и монстра. Набора «верхние карты» нет:
  отдельный узел не заводили.
- `nearest`: слоты, недостижимые по графу (не клетки поля, клетки без пути), не учитываются; свой слот карты — 0 шагов.
- `slots around ... within N`: N меньше 1 — пусто.
- Пустое значение: команда с пустой **или уничтоженной** картой ничего не делает; `==` и `!=` с пустой стороной — false;
  `for each` пропускает карты, уничтоженные по ходу цикла (набор вычисляется один раз).
- Полный слот (T075): `move` (карта не из этого слота) и `create` в слот с исчерпанной ёмкостью ничего не делают, как с
  пустым значением, и пишут предупреждение с местом команды; проверка в скрипте — `[Slot] is full`. Другие нарушения правил
  слота — ошибка исполнения.
- Перестановка карты в том же слоте хуков не вызывает.
- Реакция карты не видит данных вызвавшего скрипта (`[covering card]`, `[iterating card]` вызвавшего): вложенный запуск
  получает контекст только с `[active card]` (и `[covering card]` для `OnCovered` / `OnUnCovered`).
- Глубина вложенных реакций ограничена (`CardSystem.MaxReactionDepth` = 100): рекурсия реакций без ожидания
  переполнила бы стек раньше лимита шагов исполнителя (10 000). Лимит шагов по-прежнему действует.
- Ошибка вычисления свойства — лог с местом свойства, результат «нет».

#### Узлы ГСЧ (T072, 2026-11-04)

- `random card of [Cards]`, `random slot of [Slots]` (Model) — равновероятно из набора; пустой набор — пусто, число из ГСЧ не
  берётся. Одиночная карта или слот — набор из одного.
- `random number from [A] to [B]` (Core, `RngNodes.cs`) — целое, обе границы включительно; A больше B — ошибка исполнения
  (пустой диапазон — чаще всего ошибка в выражении границы).
- `chance [Percent]%` (Core) — условие: истинно с шансом N из 100; число из ГСЧ берётся всегда; N 0 и меньше — никогда, 100
  и больше — всегда. Шаблон — как в задаче: `%` — отдельный знак токенизатора сразу после параметра, конфликта нет; печать —
  `chance 50%`, разбор принимает и `chance 50 %`; значение — литерал, переменная или узел (`chance $p%`,
  `chance [active card].charges%`, `chance [$p + 10]%`).
- Контекст — везде (в диалогах тоже).

#### Фигуры (решено 2026-11-04, T075)

- Расстояния — в метрах, в плоскости графа (XZ локальных координат `Graph`, высота не учитывается).
- Фигуры автора: **круг** (радиус); **квадрат** с углом поворота и масштабом по осям — ромб = квадрат под
  45° со скейлом 1,5 по одной оси (сетка не квадратная); **линия** — из центра под углом на заданную
  длину, в одну или обе стороны. Остальное — комбинированием: крест — `[line 45 5m] or [line -45 5m]`.
- Повороты и масштабирование отдельными узлами — возможно позже.
- Предложено к реализации (поправить, если не так): фигура — отдельный тип без позиции, ставится на
  поле узлом `slots in [Shape] around [Card]`; над фигурами — `or` / `and` / `except`; размер квадрата —
  половина стороны (как радиус круга); линия по умолчанию в обе стороны, в одну — `ray`; клетка входит
  в линию, если её центр не дальше половины ширины карты от линии; границы включительно; угол — в
  градусах, 0° — +X графа, положительный — против часовой стрелки при взгляде сверху; клетка центра
  входит в фигуру.

##### Реализация (T075)

| Узел | Шаблон | Смысл |
|---|---|---|
| круг | `circle [Radius]m` | точки не дальше радиуса |
| квадрат | `square [Size]m`, `square [Size]m rotated [Angle]`, `square [Size]m scaled [ScaleX] [ScaleZ]`, `square [Size]m rotated [Angle] scaled [ScaleX] [ScaleZ]` | размер — половина стороны; сначала поворот, затем масштаб по осям X и Z графа |
| линия | `line [Angle] [Length]m` | из центра в обе стороны |
| луч | `ray [Angle] [Length]m` | из центра в одну сторону |
| операции | `[A] or [B]`, `[A] and [B]`, `[A] except [B]` | над множествами точек, результат — фигура |
| набор слотов | `slots in [Shape] around [Card]` | клетки поля в фигуре с центром в клетке карты, по порядку графа |

- Код: `Code/Model/Shapes/` (`Shape` — `Contains(смещение XZ, половина ширины линии)`, `CircleShape`, `SquareShape`,
  `LineShape`, операции `Shape.Union` / `Intersection` / `Difference`), узлы — `Code/Model/Cards/ShapeNodes.cs`,
  отбор клеток — `FieldSlots.GetCellsIn` (позиции — `GraphSlot.Position` графа, без сцены). Тесты —
  `Tests/EditMode/Shapes/ShapeTests.cs` (сетка 5 × 5 с шагом 1,5 × 2).
- Числа — `Evaluator<float>`: литерал с дробной частью (`1.5`, `-45`) Core уже разбирает и печатает (`Constant<float>`,
  инвариантная культура), отдельный тип значения через `AddValueType` не нужен. Переменных типа float нет, поэтому значение —
  литерал. `m` — литеральное слово шаблона сразу после параметра (как `%` у `chance`): печать `circle 2m`, разбор
  принимает и `circle 2 m`; без `m` — ошибка разбора.
- Скелеты: `[] or []` / `[] and []` / `[] except []` с результатом `Shape` не совпадают с операциями над наборами и
  условиями (ключ скелета — тип результата); в параметр-набор фигура не подходит (ошибка разбора). Четыре шаблона квадрата —
  один класс, принтер выбирает самый подробный с заданными параметрами (`rotated 0` печатается, если угол задан).
- Геометрия: плоскость XZ локальных координат графа, высота не учитывается; 0° — +X, 90° — +Z (против часовой стрелки
  при взгляде сверху); допуск границ — 1 мм (у квадрата — 1 мм вдоль меньшей оси масштаба). Центр фигуры — позиция клетки
  карты; карта не на клетке поля (рука, нет героя) — пусто. Центр входит в любой примитив (расстояние 0); `except` может его
  убрать.
- Линия — полоса шириной в карту: проекция центра клетки на направление в пределах длины (у луча — от 0), расстояние до оси —
  не больше половины ширины карты (`FieldConfig.CardSize.x / 2`; конфига нет — 0,75). Концы плоские: дальше длины линия
  не продолжается (отличие от буквального «расстояние до отрезка», где конец скруглён и добавлял бы полширины карты к
  длине).
- Масштаб после поворота (вдоль осей графа), поэтому квадрат под 45° с разным масштабом — ромб с диагоналями по осям.
  Масштаб — множитель, размер `m` — до масштаба: `square 1m scaled 1.5 2` — полуоси 1,5 × 2 м.
- Ошибки исполнения: радиус, размер, длина меньше 0; масштаб 0 и меньше.
- Отличия от предложения: крест прототипа (`Cross`, по строке и столбцу) — линии под 0° и 90°; пример автора
  `[line 45 5m] or [line -45 5m]` — косой крест (диагонали). Узлов поворота и масштаба отдельно нет.
- Фигуры прототипа (целые координаты сетки) в метрах для сетки с шагом a × b (тестовая 1,5 × 2): граница — посередине между
  последней входящей и первой не входящей клеткой, поэтому фигура не зависит от зазоров (сетка `TestLocation` с шагом
  1,1 × карта = 1,65 × 2,2 даёт те же клетки):

  | Прототип | Фигура | Сетка 1,5 × 2 |
  |---|---|---|
  | `Square N` (max(\|i\|, \|j\|) ≤ N) | `square [N + 0,5]m scaled a b` | Square 1 — `square 1.5m scaled 1.5 2`, Square 2 — `square 2.5m scaled 1.5 2` |
  | `Rhombus N` (\|i\| + \|j\| ≤ N) | `square [(N + 0,5) / √2]m rotated 45 scaled a b` | Rhombus 1 — `square 1.06m rotated 45 scaled 1.5 2`, Rhombus 3 — `square 2.47m rotated 45 scaled 1.5 2` |
  | `Cross N` | `[line 0 [(N + 0,5) · a]m] or [line 90 [(N + 0,5) · b]m]` | Cross 1 — `[line 0 2.25m] or [line 90 3m]` |
  | `Square 0` / `Distance 0` (своя клетка) | `slot of [hero]` (или `except [slot of [...]]`) | — |

## База команд (решено 2026-10-17)

- Асинхронный примитив — **UniTask** (Cysharp): работает в Web, есть `WhenAll`, интеграция с
  DOTween, окно TaskTracker. Копия UniTask внутри Naninovel — в своём namespace, не конфликтует.
- Асинхронны только **команды**: `UniTask Execute(ScriptContext)`. Мгновенные команды наследуют
  `InstantCommand` (`void Run(ScriptContext)`). **Кондишены и эвалуаторы синхронны.**
- `ScriptContext` — развитие `Context` прототипа: цепочка родителей с типизированными данными
  (`ActiveCard`, `IteratingCard`, ...; дочерний — `context.With(data)`), системы сессии через
  `context.Get<T>()`, текущий запуск и его токен отмены. Корневой контекст — на сессию;
  `Game.BaseContext` нет.
- `ScriptRunner` (система сессии): каждый запуск (хук карты, общеигровой хук, диалог) —
  зарегистрированный `ScriptExecution`. Вложенные реакции карт — внутри того же запуска.
  `Background` — отдельный запуск, токен связан с токеном scope, а не родителя. `Parallel` —
  `UniTask.WhenAll`. Команды ожидания игрока (реплика, выбор, ввод) оборачивают ожидание в
  `context.WaitForPlayer()`; `IsIdle` = активных запусков нет или все ждут игрока.
- `ScriptRunner.RunCode(name, body)` (T072) — запуск кода C# (раскладка, позже действия игрока), зарегистрированный как
  запуск секции: пока он идёт, исполнитель не простаивает, и запуски внутри него не дают точки сохранения между собой.
  Исключения кода, включая отмену, уходят вызывающему; позиции нет.
- Ошибка в команде — лог с файлом и строкой скрипта, запуск прерывается, игра продолжается.
  Отмена — тихая.
- **Скрипты разбираются из текста при загрузке** (с кешем), в редакторе — ещё и при импорте для
  проверки. Парсер — в Core, работает в билде. Команды — обычные классы: `[SerializeReference]`
  и `[Serializable]` им не нужны.

```csharp
public abstract class Command
{
    public abstract UniTask Execute(ScriptContext context);
}

public abstract class InstantCommand : Command
{
    public sealed override UniTask Execute(ScriptContext context)
    {
        Run(context);
        return UniTask.CompletedTask;
    }

    protected abstract void Run(ScriptContext context);
}

public abstract class Condition
{
    public abstract bool Check(ScriptContext context);
}

public abstract class Evaluator<T>
{
    public abstract T Evaluate(ScriptContext context);
}
```

## Исполнитель и управляющие команды (решено 2026-10-17)

Управляющие конструкции исполняет сам `ScriptRunner` по явному стеку кадров, а не C#-рекурсия:
асинхронный метод нельзя сохранить посреди выполнения, а стек кадров — данные.

- **Обычные команды** — `UniTask Execute(ScriptContext)`, подавляющее большинство.
- **Управляющие команды** (`if`, `choice` / `option`, `goto`, `call`, `return`) свои блоки не
  выполняют, а возвращают шаг исполнителю:

```csharp
public abstract class ControlCommand : Command
{
    // Enter(block) | Jump(section) | Call(section) | Return
    public abstract UniTask<ControlStep> Next(ScriptContext context);
}

[Script("if", "if [Condition] {OnTrue} else {OnFalse}")]
public class Branch : ControlCommand
{
    public Condition Condition;
    public List<Command> OnTrue;
    public List<Command> OnFalse;

    public override UniTask<ControlStep> Next(ScriptContext context)
        => UniTask.FromResult(ControlStep.Enter(Condition.Check(context) ? OnTrue : OnFalse));
}
```

- Кадр: файл, секция, блок, индекс команды; стек `call` — часть стека кадров. `goto` снимает
  кадры текущей секции и кладёт кадр целевой; `call` кладёт кадр с возвратом; `return` снимает.
- `choice` — управляющая команда с ожиданием игрока: показывает варианты, ждёт выбора, возвращает
  `Enter(тело варианта)`.
- `Parallel`, `Background`, циклы (`for each card`) — обычные команды; свои блоки запускают как
  вложенные запуски (`context.Runner.RunBlock(...)`). Позиция внутри них не сохраняется — в
  диалогах команды ожидания внутри них запрещены (валидатор).
- Реакции карт — вложенные запуски изнутри обычных команд.
- Один исполнитель для всех файлов (скрипты и диалоги).
- Реализация (T054, `Code/Core/Scripting/`): `goto` внутри `call` сохраняет кадр вызова — после
  целевой секции исполнение возвращается к вызвавшему (как `jump` в Ren'Py). `ControlCommand`
  объявляет свои блоки (`BlockCount` / `GetBlock`) — по ним строится путь позиции. Во вложенных
  ветках (`parallel`, `RunSection`) `goto` / `return` действуют в пределах ветки.
- Известные ограничения: ожидание игрока учитывается на весь запуск (если одна ветка `parallel`
  ждёт игрока, а другая анимируется, запуск считается ждущим — в диалогах это закрыто запретом
  ожидания внутри `parallel`); долгие команды обязаны слушать `context.Cancellation`, иначе при
  ошибке соседней ветки `parallel` остаётся «хвост».
- Плюсы: `goto` / `call` без раскрутки исключениями, точная позиция в ошибках и для подсветки
  строки в инспекторе, позиция исполнения сериализуема.

## Почему ломались скрипты карт

54 файла (конфиги, префабы, все сцены) сериализованы Odin с `SerializedFormat: 0` — бинарный
блоб внутри YAML с полными именами типов (`XandArt.TheGrowth.Common.Random`1[[...SlotEntity, Code]], Code`).
Переименование класса, перенос namespace или сборки теряет данные. GUID ассетов ни при чём.

## `[SerializeReference]` — для остальных полиморфных конфигов

Скрипты хранятся текстом. `[SerializeReference]` остаётся для прочих полиморфных данных в
конфигах — например, список компонентов карты.

- `[SerializeReference] List<ICardSettings>` — список разнотипных объектов. Стандартный инспектор
  не умеет добавлять элемент с выбором типа → нужен drawer с выбором типа (или Odin как drawer).
- Кастомный инспектор для отдельного класса возможен: drawer выбора типа делегирует отрисовку
  drawer'у конкретного типа. Подбирает ли Unity 6 drawer по конкретному типу сам — проверить.
- Ограничения: тип значения `[Serializable]`, не абстрактный, не `UnityEngine.Object`; generic-типы
  поддерживаются (Unity 2023.1+); каждое вложенное полиморфное поле тоже `[SerializeReference]`;
  `Dictionary`/`HashSet` не сериализуются; переименования — `[MovedFrom]`; данные пропавших типов
  сохраняются (валидатор: `SerializationUtility.HasManagedReferencesWithMissingTypes`).
- Ловушка: дублирование элемента списка в инспекторе копирует ссылку, а не объект.

1. Пока классы на Odin — выгрузить все скриптовые данные общим reflection-дампером

5. Удаление Odin — сразу после инспектора скриптов, до экспедиции в 3D (решено 2026-11-04). Порядок
